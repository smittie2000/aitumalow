# Aitumalow 0.6.0

Released 2026-09-30.

Agents and people can now use the same workflow catalog and authoring controls.
An agent can discover configuration schemas and create a complete inactive draft
in two MCP calls, then inspect, edit, test, publish and recover executions using
the same package services as the visual editor. Workflow definitions are stored
data; creating a workflow does not require new PHP in the host application.

## Authoring improvements

- Schedule forms offer recurrence, local time, days and timezone while preserving
  cron expressions and custom schedules.
- Empty workflows open trigger selection. Save settings and add a connected next
  step directly from the settings panel.
- Configuration controls have accessible names; failed creation retains entered
  values and explains the error.
- Run history refreshes while open and discards responses for a previous workflow.
- MCP exposes 33 tools, including organization, expression variables, draft tests,
  run recovery, and immutable revision review and restoration. Complete graphs
  open with separated node positions. Copies start without a live revision.
- Editor route binding and MCP queries honor configured model subclasses and
  scopes. Folder/tag assignment also checks visibility before saving.

The dedicated browser test area has persisted test leads, tickets and bookings,
a real queue worker, a local SMTP inbox, and captured call requests. Five browser
scenarios cover lead-owner email, creation retry, ticket reminders, booking calls,
and an MCP-created workflow edited and executed through the interface. Captured
calls verify the workflow request; they do not establish live telephony delivery.
See [browser testing](../advanced/browser-testing.md).

## Requirements and upgrade

Use PHP 8.4+, Laravel 13.30+, Filament 5 and Durable Workflow 2.2.21+.
Optional MCP support is validated against Laravel MCP 1.0.1. The compiled editor
uses React Flow 12.12.0 and ships with the package.

```bash
composer require 'aitumalow/aitumalow:^0.6.0' --no-update
composer update aitumalow/aitumalow durable-workflow/workflow --with-dependencies
php artisan migrate --force
php artisan filament:assets
php artisan workflow:v2:doctor --strict
```

Aitumalow adds no new migration in this release. Durable adds runtime migrations;
apply every pending migration with the normal deployment process. In a host
already running Durable 2.2.14, the new migration indexes schedule occurrences.
For older installations, review [runtime upgrade guidance](../advanced/execution-engine.md).
Deploy the matching compiled editor and restart long-lived queue workers through
the host's normal deployment process.

Keep the native `workflow:v2:schedule-tick` command in the Laravel scheduler and
run the scheduler continuously. The queue must process the configured Aitumalow
queue. A web server alone does not execute scheduled workflows.

## Host authorization and capabilities

Mount the MCP server in a host-owned authenticated route group with the same
workflow-management permission as the editor. Bind the host execution-scope
resolver so references and actions receive the authenticated user's identity.
Use configured models for the host's record visibility rules; the package does
not invent a tenant or grant domain permissions from a workflow definition.

Existing registered host actions, subjects and scheduled sources appear in both
interfaces without rebuilding the package. Installing Aitumalow does not expose
arbitrary app models, PHP execution or unrestricted provider operations. A new
business capability still needs a bounded host integration; once registered,
users and agents compose workflows from it without adding app code per workflow.
See [MCP integration](../mcp.md) and [scheduled host agents](../examples/scheduled-host-agents.md).
