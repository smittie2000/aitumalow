# Aitumalow 0.5.0 release notes

The workflow editor now saves each graph gesture atomically, supports undo/redo,
and provides a larger workspace for inspecting a step's input, settings and
output. Durable Workflow remains the embedded execution engine, upgraded from
2.0.9 to 2.0.14.

## Editor and graph API

- Insert a step directly into a connection, append from an output, drop an
  output onto empty canvas, or double-click the canvas to add a step. Multiport
  steps expose an explicit port choice before connecting.
- Start empty workflows with a trigger, search existing steps, and use keyboard
  navigation in the action picker. New steps avoid occupied canvas space;
  saved positions remain until an explicit move or Auto Layout.
- Undo and redo graph edits, including node removal, insertion, multi-node moves,
  settings and pins. Lost-response retries reuse the same request receipt;
  conflicting changes prompt a reload instead of overwriting newer edits.
- Keep unsaved step settings while navigating, then save names and configuration
  together. Drafts may be incomplete; publication and tests still validate them.
- Expand a step to inspect input, settings and output together. Browse table or
  JSON data, switch output ports, and distinguish pinned samples, draft tests and
  historical runs. Test data identifies its run/revision and becomes stale after
  graph edits.

HTTP, PHP and optional MCP clients share the same
[graph editing contract](/advanced/graph-editing). The
[package design guide](/advanced/package-design) explains the n8n-inspired
authoring patterns and the ownership split between Laravel hosts, Aitumalow and
Durable. No n8n code, assets or connector catalog is included.

## Durable Workflow upgrade

The Composer requirement is now `durable-workflow/workflow:^2.0.14`.
The reviewed upstream releases since 2.0.9 cover:

| Release | Change |
| --- | --- |
| [2.0.10](https://github.com/durable-workflow/workflow/releases/tag/2.0.10) | Laravel's native MariaDB driver passes backend readiness checks. |
| [2.0.11](https://github.com/durable-workflow/workflow/releases/tag/2.0.11) | Expired activity deadlines survive worker lease repair, preventing late completions and extra attempts. |
| [2.0.12](https://github.com/durable-workflow/workflow/releases/tag/2.0.12) | Due schedules retain fractional timestamp precision and occurrence identity. |
| [2.0.13](https://github.com/durable-workflow/workflow/releases/tag/2.0.13) | Monitoring projections reuse loaded rows and metadata, reducing repeated queries. |
| [2.0.14](https://github.com/durable-workflow/workflow/releases/tag/2.0.14) | Mutating a Carbon timestamp returned by the deterministic clock cannot advance stored workflow time. |

The [source comparison](https://github.com/durable-workflow/workflow/compare/2.0.9...2.0.14)
contains no database migration, dependency-requirement or incompatible public
signature changes. Aitumalow's runtime adapters and replay identities require
no changes. Long-running PHP workers must reload the updated dependency.

## Upgrade an existing application

PHP 8.4+, Laravel 13 and Filament 5 requirements are unchanged. Because `^0.4.0`
does not include `0.5.0`, update the host's package constraint explicitly:

```bash
composer require aitumalow/aitumalow:^0.5.0 --with-dependencies --minimal-changes
php artisan migrate
php artisan workflow:v2:doctor --strict
php artisan filament:upgrade
```

Restart long-running workflow/queue workers through the host's normal deployment
process. Compiled standalone and embedded editor assets ship with the package.
Deploy the PHP API and matching editor assets together.

The additive `2026_09_13_000001_create_workflow_graph_edits_table.php` migration
creates edit receipts. Existing graph, published revision and Durable tables are
unchanged. Table/model names are configurable; existing published configuration
uses the new defaults automatically. Receipts retain before/after graph documents,
including settings and pinned samples, until the host removes them or hard-deletes
the workflow. Their retention is separate from Durable execution history.

Hosts registering `EditorApiRoutes::register()` receive the new graph endpoints
automatically. Hosts maintaining their own route lists must add
`GET /workflows/{workflow}/graph` and `POST /workflows/{workflow}/graph-edits` with
the same workflow access controls. Custom injected SDKs must implement
`graph.get()` and `graph.edit()`; `createEditorSdk()` already provides both.
The existing whole-draft API remains available.

Verify a representative workflow in the consuming application's own environment,
including adding/saving steps, tests, wait/resume and failure handling.

## Validation

- 248 PHP tests passed with 1,150 assertions against Durable Workflow 2.0.14.
- PHPStan, formatting and Rector checks passed. Composer validation passed and
  the dependency update reported no security advisories.
- Six UI test files, ESLint, TypeScript and standalone/embedded builds passed.
- Fourteen browser fixture scenarios covered insertion, retries, conflicts,
  undo/redo, navigation, selection, settings, data previews and mobile/dark views.

Browser fixtures validate the shipped editor; consuming applications still own
their authorization, database and deployment verification.
